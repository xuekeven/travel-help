# 出行订单模块草案

> 日期：2026-05-31  
> 状态：基础版已实现

## 一、目标

在「购票计划」和「候补订单」中间新增「出行订单」模块，用于展示 12306「未出行订单」数据，并在出行前 2 天、1 天和当天发送出行提醒。

数据由 Chrome 插件在用户打开 12306 未出行订单页面时获取，并同步到本服务。插件会先过滤「已退票」「已改签」「已出站」订单，仅上报有效未出行订单。同步策略与候补订单保持一致：插件始终上报当前最新有效列表，服务端全量替换本地数据；当 12306 返回空列表或过滤后无有效订单时，也同步空数组并清空本地出行订单数据。

## 二、数据来源

接口地址：

```text
https://kyfw.12306.cn/otn/queryOrder/queryMyOrder
```

插件只处理上述「未出行订单」接口，明确忽略 `https://kyfw.12306.cn/otn/queryOrder/queryMyOrderNoComplete`。后者是「未完成订单」接口，不参与出行订单同步。

核心响应路径：

```text
data.OrderDTODataList[]
```

一条 `OrderDTODataList` 代表一个 12306 订单，内部的 `tickets[]` 代表该订单下的车票。当前模块按“订单”存储，一条订单入库一行。

## 三、表结构草案

Prisma 模型建议：

```prisma
model TravelOrder {
  id                  String   @id @default(uuid())
  orderNo             String   @unique                 // sequence_no，12306 订单号
  orderDate           DateTime                         // order_date，下单时间

  departureDate       DateTime @db.Date                // train_date / train_date_local
  departureTime       String                           // start_time_page，例如 "20:12"
  arrivalDate         DateTime? @db.Date               // arrive_date_local，可为空
  arrivalTime         String                           // arrive_time_page，例如 "22:21"

  fromStation         String                           // from_station_name_page[0] 或 ticket.stationTrainDTO.from_station_name
  toStation           String                           // to_station_name_page[0] 或 ticket.stationTrainDTO.to_station_name
  trainCode           String                           // train_code_page 或 station_train_code
  trainNo             String?                          // trainDTO.train_no
  distance            Int?                             // stationTrainDTO.distance

  passengerNames      String[]                         // array_passser_name_page 或 tickets[].passengerDTO.passenger_name
  seatTypeNames       String[]                         // tickets[].seat_type_name，保留每张票
  coachNames          String[]                         // tickets[].coach_name
  seatNames           String[]                         // tickets[].seat_name
  ticketTypeNames     String[]                         // tickets[].ticket_type_name
  ticketStatusNames   String[]                         // tickets[].ticket_status_name

  ticketCount         Int                              // ticket_totalnum
  totalPrice          Decimal  @db.Decimal(10, 1)      // ticket_total_price_page，单位：元
  ticketSnapshots     Json                             // tickets[] 的列表展示摘要，保留多票明细

  cancelFlag          String?                          // cancel_flag
  resignFlag          String?                          // resign_flag
  returnFlag          String?                          // return_flag
  payFlag             String?                          // pay_flag
  confirmFlag         String?                          // confirm_flag
  orderStatus         String?                          // 从票状态汇总出的展示状态，如"已支付"

  rawData             Json                             // 原始 OrderDTODataList，保留完整字段
  syncedAt            DateTime @default(now()) @updatedAt
  createdAt           DateTime @default(now())

  @@map("travel_orders")
}
```

### 字段取值说明

| 展示字段 | 优先取值 | 备注 |
|----------|----------|------|
| 日期 | `tickets[0].train_date_local` / `tickets[0].train_date` | 入库为 `departureDate` |
| 时间 | `start_time_page` / `arrive_time_page` | 只存 `HH:mm` 字符串，便于展示和排序 |
| 始发站 / 终到站 | `from_station_name_page[0]` / `to_station_name_page[0]` | 兜底取 `tickets[0].stationTrainDTO` |
| 车次 | `train_code_page` | 兜底取 `tickets[0].stationTrainDTO.station_train_code` |
| 乘车人 | `array_passser_name_page` | 兜底取 `tickets[].passengerDTO.passenger_name` |
| 座位类型 | `tickets[].seat_type_name` | 多张票保留数组 |
| 座位号 | `tickets[].coach_name + tickets[].seat_name` | 示例：`01车 04D号` |
| 票价 | `ticket_total_price_page` | 单位统一为元；不要直接使用 `ticket_price` 分值字段 |
| 订单状态 | `tickets[].ticket_status_name` 汇总 | 示例：全部为 `已支付` 时展示 `已支付` |

### 为什么不拆 ticket 表

当前需求的业务入口是“未出行订单列表”，同步策略也是全量替换，暂时没有对单张票做独立生命周期管理的需求。按订单存储更简单，列表展示需要的多票信息用数组字段和 `ticketSnapshots` 承载即可。

如果后续要做“按乘车人过滤”“逐张票退改签提醒”“每张票独立状态统计”，再引入 `TravelOrderTicket` 子表会更合适。

## 四、同步 API 草案

新增接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/travel-orders` | 获取出行订单列表，默认按 `departureDate asc, departureTime asc` 排序 |
| `POST` | `/api/travel-orders/sync` | Chrome 插件同步最新未出行订单数据 |

插件运行记录需要输出过滤统计，例如：

```text
[12306助手] 检测到 5 条出行订单，其中 2 条已退票订单，1 条已改签订单，2 条有效订单，准备同步...
[12306助手] 已同步 2 条出行订单到 https://homeserver.tailed5977.ts.net/12306
```

同步请求体：

```json
{
  "orders": [
    {
      "sequence_no": "E109095376",
      "order_date": "2026-05-19 08:41:40",
      "ticket_totalnum": 1,
      "ticket_total_price_page": "140.5",
      "start_train_date_page": "2026-06-01 20:12",
      "start_time_page": "20:12",
      "arrive_time_page": "22:21",
      "train_code_page": "D927",
      "array_passser_name_page": ["张三"],
      "from_station_name_page": ["北京西"],
      "to_station_name_page": ["邯郸东"],
      "tickets": []
    }
  ]
}
```

同步规则：

| 场景 | 行为 |
|------|------|
| `orders` 是非空数组 | 删除旧的 `travel_orders` 数据，再批量写入新数据 |
| `orders` 是空数组 | 删除旧的 `travel_orders` 数据，返回 `count: 0` |
| 缺少订单号 | 返回 `400`，提示数据格式不正确 |
| 非 mock 模式 Token 错误 | 返回 `401 Unauthorized` |

## 五、列表展示草案

模块位置：购票计划和候补订单之间。

标题说明建议：

```text
安装 Chrome 插件后，打开 12306 未出行订单页面即可自动同步；系统会在出行前 2 天、1 天和当天的 00:00 发送出行提醒。
```

列表字段建议：

| 字段 | 展示方式 |
|------|----------|
| 出行日期 | `2026-06-01 周一` |
| 时间 | `20:12 → 22:21` |
| 始发站 | `北京西` |
| 终到站 | `邯郸东` |
| 车次 | `D927` |
| 乘车人 | 多人用 `、` 拼接 |
| 座位类型 | 多票去重后展示，如 `二等座` |
| 座位号 | 多票展示为 `01车 04D号`，多人换行或逗号拼接 |
| 票价 | `¥140.5` |
| 退票费 | 展示当前时间之后仍有效的退票费规则节点；“开车前 8 天以上”按 12306 自然日边界判断，如 6月19日车票在6月11日当天仍按 0 元展示 |
| 最近同步 | 取所有订单最大 `syncedAt`，展示在筛选区域 |

## 六、出行提醒草案

每日 **00:00（Asia/Shanghai）** 扫描出行订单：

| 触发条件 | 说明 |
|----------|------|
| 出行日期 = 今天 + 2 天 | 发送“还有2天出行”提醒 |
| 出行日期 = 今天 + 1 天 | 发送“还有1天出行”提醒 |
| 出行日期 = 今天 | 发送“今天就要出行”提醒 |

只提醒有效未出行订单：插件同步前已过滤「已退票」「已改签」「已出站」订单；服务端提醒任务也会再次排除已取消、已退票、已改签、已出站、已关闭等非有效状态。

提醒格式建议：

```text
【2026-06-01】【周一】【20:12】【北京西】到【邯郸东】的【D927】次列车还有2天就要出行了，乘车人：【张三】，座位：【二等座 01车04D号】，请提前安排出行
【2026-06-01】【周一】【20:12】【北京西】到【邯郸东】的【D927】次列车今天就要出行了，乘车人：【张三】，座位：【二等座 01车04D号】，请提前安排出行
```

如果一单多张票，乘车人和座位用顿号拼接。
