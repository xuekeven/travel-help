## 1. 项目启动

### 1.1 真实数据库开发环境

```bash

```

- 使用 `.env` 中的 `DATABASE_URL` 连接真实 PostgreSQL。
- 默认访问地址：`http://localhost:3005/12306`。
- 页面包含三个模块：购票计划、出行订单、候补订单。

```bash

```

- 使用 `lib/mock-data.ts` 中的内存数据，不连接真实数据库。
- 默认访问地址：`http://localhost:3006/12306`。
- 用于快速验证列表展示、排序、空数据同步和提醒文案。

## 2. 数据库与 Prisma

当前 Prisma schema 位于 `prisma/schema.prisma`，包含三张业务表：

| 表 | Prisma Model | 用途 |
| --- | --- | --- |
| `travel_plans` | `TravelPlan` | 购票计划，记录用户关注的未来出行和开售日期 |
| `travel_orders` | `TravelOrder` | 出行订单，来自 12306「未出行订单」接口 |
| `waitlist_orders` | `WaitlistOrder` | 候补订单，来自 12306 候补订单接口 |

新增或更新迁移后，生产环境按顺序执行：

```bash
pnpm prisma migrate deploy
pnpm prisma generate
pnpm build
```

说明：

- `migrate deploy` 只执行已经提交到仓库的迁移文件，适合生产环境。
- `prisma generate` 重新生成 `@prisma/client`，否则新增 Model 后构建可能提示 `PrismaClient` 上没有对应属性。
- `pnpm build` 会同时验证 Next.js 编译和 TypeScript 类型。

## 3. 购票计划

### 3.1 当前规则

- 模块名称：购票计划。
- 原「出行计划」已统一改名为「购票计划」。
- 开售日期按出行日期提前 14 天自动计算。
- 状态只包含 `待开售`、`已开售`，由开售日期自动计算，不再手动选择。
- 列表字段顺序：出行日期、节假日信息、开售日期、状态、始发站、终到站、座位、张数、备注、操作。
- 表单弹层字段顺序与列表保持一致，并在开售日期后展示自动生成的状态列。
- `PlanStatusTag` 渲染状态文字，不使用额外背景色。

## 4. 出行订单

### 4.1 当前规则

- 模块位置：购票计划和候补订单之间。
- 数据来源：Chrome 插件拦截 `https://kyfw.12306.cn/otn/queryOrder/queryMyOrder`。
- 明确忽略 `https://kyfw.12306.cn/otn/queryOrder/queryMyOrderNoComplete`，该接口是「未完成订单」，不是「未出行订单」。
- 一条数据按「订单」存储，票信息保存在 `ticketSnapshots` 和多值数组字段中。
- 插件同步前过滤「已退票」「已改签」「已出站」订单，仅推送有效未出行订单，并在运行记录输出过滤统计。
- 插件始终同步最新有效数据；12306 返回空列表或过滤后无有效订单时也同步 `orders: []`，服务端清空本地 `travel_orders`。
- 列表支持按出发时间升序/降序排序。
- 最近同步时间展示在筛选区域。

### 4.2 列表展示

当前表格采用卡片式视觉，字段包含：

| 字段 | 说明 |
| --- | --- |
| 出行日期 | 车票出行日期 |
| 订票日期 | 订单创建日期 |
| 车次/始发站/终到站 | 车次在前，始发站和终到站之间使用向右箭头 |
| 出发/到达时间 | 显示在对应站点下方，并与站点居中对齐 |
| 乘车人 | 多乘车人合并展示 |
| 席位 | 展示为 `XX车XX号`，避免重复追加「号」 |
| 票价 | 订单总票价 |
| 退票费 | 只展示当前时间之后仍有效的退票费规则节点；“开车前 8 天以上”按 12306 自然日边界判断 |

退票费示例：

```text
6月10号22点13分前退票费0元
6月12号22点13分前退票费10元
6月15号22点13分前退票费20元
```

## 5. 候补订单

### 5.1 当前规则

- 数据来源：Chrome 插件拦截 12306 候补订单页面接口。
- 插件始终同步最新数据；12306 返回空列表时也同步 `orders: []`，服务端清空本地 `waitlist_orders`。
- 服务端按「出发日期 + 始发站 + 终到站」聚合成组。
- 筛选组件与出行订单共用公共样式组件，同一个筛选维度内通过上下箭头切换升序/降序。
- 支持按出发时间和订单票价排序，组间排序与组内排序保持一致。
- 最近同步时间展示在筛选区域。

### 5.2 相关代码

| `components/SortSegmentedControl.tsx` | 出行订单和候补订单共用筛选组件 |

## 6. Chrome 插件

### 6.1 生效页面

插件通过 `extension/manifest.json` 注入到：

- `https://kyfw.12306.cn/otn/view/lineUp_order.html`
- `https://kyfw.12306.cn/otn/view/train_order.html`

### 6.2 页面能力

- 页面右上角显示状态条，默认宽度 100，可拖动。
- 状态条只展示状态文案，不展示插件名称和描述。
- 点击状态条打开 `320 * 400` 的日志弹层。
- 日志时间展示到秒，不展示毫秒。
- 日志弹层可拖动，并支持上下滚动。

## 7. 定时任务与通知

`lib/cron.ts` 当前注册一个每日任务：

```text
0 0 * * * Asia/Shanghai
```

任务一次性处理三类提醒：

| 类型 | 触发对象 |
| --- | --- |
| 购票提醒 | 开售前 1 天、开售当天 |
| 出行订单提醒 | 出行前 2 天、1 天、当天 |
| 候补订单提醒 | 出行前 2 天、1 天、当天 |

通知发送统一走 `lib/notify.ts` 的 `sendWeComMessage(content)`，企业微信配置见 `docs/6.企微通知.md`。
