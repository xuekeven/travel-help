# 企微通知 · wework-send 接入说明

本项目的购票提醒、出行订单提醒、候补提醒、测试通知等 **不直连企业微信 API**，而是通过 Tailnet 内的 **wework-send** 中转服务发送文本消息。

## 架构

```
12306-help（homeserver）
    │  POST /wework/send/message
    │  Authorization: Bearer <WEWORK_RELAY_API_KEY>
    ▼
wework-send（aliserver :5001）
    │  企微官方 API
    ▼
企业微信 App
```

代码入口：`lib/notify.ts` → `sendWeComMessage(content)`，被统一提醒队列消费者和
`POST /api/notify/test` 调用。

### 上游 API（wework-send）

**元数据**（无需鉴权）：

```http
GET /wework/send
```

**发送文本**：

```http
POST /wework/send/message
Authorization: Bearer <RELAY_API_KEY>
Content-Type: application/json
Idempotency-Key: <REMINDER_DEDUPE_KEY>

{ "content": "消息正文" }
```

可选字段 `touser`：企微成员 **userid**（非姓名）；多人用 `|` 分隔。不传或为空时按 **@all** 发送。

```json
{ "content": "只给你", "touser": "ZhangSan" }
```

成功：`{ "errcode": 0, "errmsg": "ok" }`

常见失败：


| HTTP | 含义                       |
| ---- | ------------------------ |
| 401  | `RELAY_API_KEY` 错误       |
| 400  | `content` / `touser` 不合法 |
| 502  | 企微侧调用失败                  |

## 12306-help 环境变量

在 **homeserver**（或本地开发机）的 `.env` 中配置：

```bash
# wework-send 基址（无末尾斜杠，不含 /wework/send）
WEWORK_RELAY_BASE_URL="http://aliserver.tailed5977.ts.net:5001"

# 与 wework-send 服务端 RELAY_API_KEY 一致
WEWORK_RELAY_API_KEY="你的密钥"

# 可选：指定接收人 userid；留空则 @all
WECOM_TO_USER=""
```


| 变量                      | 必填  | 说明               |
| ----------------------- | --- | ---------------- |
| `WEWORK_RELAY_BASE_URL` | 否*  | 未填则只打控制台日志，不真正发送 |
| `WEWORK_RELAY_API_KEY`  | 否*  | 与上成对配置           |
| `WECOM_TO_USER`         | 否   | 映射为请求体 `touser`  |


 生产环境建议两项都填；开发时可暂不填，用测试接口验证逻辑。

**网络**：运行 12306-help 的机器须能访问 `aliserver:5001`（同一 Tailscale 账号、双方在线）。

## 验证

### 1. 检查 wework-send 是否可达（在 homeserver 或 Mac）

```bash
curl -sS "http://aliserver.tailed5977.ts.net:5001/wework/send"
```

应返回 JSON 元数据。

### 2. 直接调 wework-send（带密钥）

```bash
curl -sS -X POST "http://aliserver.tailed5977.ts.net:5001/wework/send/message" \
  -H "Authorization: Bearer 你的RELAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content":"wework-send 直连测试"}'
```

### 3. 经 12306-help 测试接口

```bash
curl -sS -X POST "http://localhost:3005/api/notify/test" \
  -H "X-Sync-Token: 你的EXTENSION_SYNC_TOKEN"
# 生产：
curl -sS -X POST "https://homeserver.tailed5977.ts.net/12306/api/notify/test" \
  -H "X-Sync-Token: 你的EXTENSION_SYNC_TOKEN"
```

- 已配置中转：`{"success":true,"relay":true,...}`，企微 App 收到消息  
- 未配置：`relay:false`，仅服务器 `pm2 logs` 有 `[企微通知]` 打印  
- 配置错误或服务异常：`502` + `error` 字段

## 定时任务

`lib/cron.ts` 每分钟消费 `reminder_tasks` 中已到期且可重试的任务。购票计划和
订单同步时会预先生成持久化任务，因此服务在计划触发时刻短暂重启、数据库临时异常或
企微不可用后，仍能在有效期内补发。订单的 00:00 提醒保留 24 小时有效期。

消费者先用数据库条件更新原子抢占任务并提交，再在事务外调用中转服务。请求超时为
10 秒；发送失败不会中断后续任务，而是按 1、2、5、10、30、60 分钟退避。
`PROCESSING` 状态使用 2 分钟租约，进程中断后可自动回收。发送请求携带
`Idempotency-Key`，中转服务应按该键去重。未配置企微中转时任务保持待发送状态。

购票提醒规则：


| 触发条件      | 消息格式                                          |
| --------- | --------------------------------------------- |
| 到达售前 24 小时 | `【2026-06-01】【周一】【北京西】到【邯郸东】的火车票，【开售时间：2026-05-18 周一 08:00】，这是售前 24 小时提醒，请关注` |
| 到达售前 15 分钟 | `【2026-06-01】【周一】【北京西】到【邯郸东】的火车票，【开售时间：2026-05-18 周一 08:00】，这是售前 15 分钟提醒，请关注` |


候补提醒规则：


| 触发条件 | 消息格式 |
| -------- | -------- |
| 候补订单仍未成功，且还有 2 / 1 天出行 | `【2026-06-01】【周一】【北京西】到【邯郸东】的候补订单【订单号E123456789】还没有候补成功，还有2天就要出行了，请考虑【买长乘短、买短乘长、更换交通方式】等方案` |
| 候补订单仍未成功，且当天出行 | `【2026-06-01】【周一】【北京西】到【邯郸东】的候补订单【订单号E123456789】还没有候补成功，今天就要出行了，请考虑【买长乘短、买短乘长、更换交通方式】等方案` |

出行订单提醒规则：

| 触发条件 | 消息格式 |
| -------- | -------- |
| 有效未出行订单还有 2 / 1 天出行 | `【2026-06-01】【周一】【20:12】【北京西】到【邯郸东】的【D927】次列车还有2天就要出行了，乘车人：【张三】，座位：【二等座 01车04D号】，请提前安排出行` |
| 有效未出行订单当天出行 | `【2026-06-01】【周一】【20:12】【北京西】到【邯郸东】的【D927】次列车今天就要出行了，乘车人：【张三】，座位：【二等座 01车04D号】，请提前安排出行` |


日志只记录任务 ID、消息长度、幂等键和错误原因，不记录完整通知正文。

## 安全建议

1. `**WEWORK_RELAY_API_KEY` 只写在 `.env`**，勿提交 git。
2. wework-send 与 12306-help 均仅在 **Tailnet** 暴露，勿将 5001 端口映射到公网。
3. `WECOM_TO_USER` 填 **userid**，不是显示姓名。
4. 密钥轮换时：先改 aliserver 上 wework-send，再改 12306-help `.env` 并 `pm2 reload`。
