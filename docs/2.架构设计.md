## 二、技术选型

### 2.1 主要技术栈

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| **前端框架** | Next.js 15（App Router）+ TypeScript | 前后端同构，前端工程师入门全栈最低门槛；App Router 是目前主流推荐 |
| **UI 样式** | SCSS（CSS Modules） | 前端工程师熟悉，作用域隔离不污染全局，Next.js 开箱支持 |
| **UI 组件库** | Ant Design 5（antd） | 组件丰富完整（Table/Form/Modal/Tag 等），中文生态好，个人工具场景非常合适 |
| **后端** | Next.js API Routes（Route Handlers） | 与前端同项目同语言，无需单独维护后端服务 |
| **数据库** | PostgreSQL 16 | 全栈主流选择，功能强大，JSON 支持好（候补原始数据用 JSONB 存储） |
| **ORM** | Prisma | Schema 即类型，自动生成 TypeScript 类型，迁移体验好，对前端工程师友好 |
| **定时任务** | node-cron | 轻量，纯 Node.js，无需额外进程；在 Next.js 中通过 `instrumentation.ts` 启动 |
| **浏览器插件** | Chrome Extension Manifest V3 | 规避 12306 反爬，复用真实会话 |
| **内网穿透** | Tailscale | 家庭服务器与 Mac 之间建立虚拟局域网，安全稳定，无需公网端口映射 |
| **包管理** | pnpm | 速度快，磁盘占用少 |
| **运行时** | Node.js 20 LTS | 稳定版本，长期支持 |

### 2.2 暂不引入的技术（及原因）

| 技术 | 暂不引入原因 |
|------|-------------|
| Redis | 个人工具无高并发缓存需求 |
| Docker | 初期保持简单，后期可按需容器化 |
| 消息队列（如 BullMQ） | 任务量极小，node-cron 足够 |
| 鉴权（NextAuth 等） | 单用户工具，Tailscale 内网访问，无需额外鉴权层 |

## 四、数据库设计

### 4.1 完整 Prisma Schema

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// 座位类型枚举
enum SeatType {
  SECOND_CLASS   // 二等座
  FIRST_CLASS    // 一等座
  BUSINESS       // 商务座
  HARD_SLEEPER   // 硬卧
  SOFT_SLEEPER   // 软卧
  HARD_SEAT      // 硬座
  NO_SEAT        // 无座
}

// 出行计划状态枚举
enum PlanStatus {
  PENDING_SALE   // 待开售
  ON_SALE        // 已开售（抢票中）
  WAITLISTED     // 候补中
  SUCCESS        // 购票成功
  FAILED         // 购票失败
  CANCELLED      // 已取消
}

// 出行计划表
model TravelPlan {
  id             String     @id @default(uuid())
  departureDate  DateTime   @db.Date              // 出行日期
  holidayName    String?                           // 节假日名称（可为空）
  fromStation    String                            // 始发站
  toStation      String                            // 终到站
  seatType       SeatType                          // 座位类型
  ticketCount    Int        @default(1)            // 购票张数
  status         PlanStatus @default(PENDING_SALE) // 状态
  remark         String?                           // 备注
  createdAt      DateTime   @default(now())
  updatedAt      DateTime   @updatedAt

  @@map("travel_plans")
}

// 候补订单表
model WaitlistOrder {
  id            String   @id @default(uuid())
  orderNo       String   @unique                  // 12306 订单号（唯一键）
  departureDate DateTime @db.Date                 // 出发日期
  fromStation   String                            // 始发站
  toStation     String                            // 终到站
  trainNumbers  String[]                          // 候补车次列表
  seatType      String                            // 座位类型
  ticketCount   Int                               // 候补张数
  price         Decimal  @db.Decimal(8, 1)        // 票价
  departureTime String                            // 出发时间 "08:00"（字符串存储方便排序）
  arrivalTime   String                            // 到达时间
  status        String                            // 候补状态（来自 12306）
  rawData       Json                              // 原始 JSON 数据
  syncedAt      DateTime @default(now()) @updatedAt // 最近同步时间
  createdAt     DateTime @default(now())

  @@map("waitlist_orders")
}
```

### 4.2 关键设计说明

| 决策 | 说明 |
|------|------|
| `departureDate` 用 `@db.Date` | 只存日期不存时间，避免时区转换问题 |
| `departureTime` 用字符串 `"08:00"` | 直接用字符串比较即可排序，简单可靠 |
| `trainNumbers` 用 `String[]` | PostgreSQL 原生支持数组类型 |
| `rawData` 用 `Json` (JSONB) | 保留 12306 原始数据，后续功能扩展不需要改表结构 |
| `orderNo` 设置 `@unique` | 支持 upsert，多次同步不重复入库 |

## 五、API 接口设计

### 5.1 出行计划

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/plans` | 获取所有出行计划，支持 `?status=` 过滤 |
| `POST` | `/api/plans` | 新增出行计划（body 中无 id） |
| `POST` | `/api/plans/:id` | 更新出行计划（body 中携带修改字段） |
| `DELETE` | `/api/plans/:id` | 删除出行计划 |

> **为什么用 POST 而不是 PUT/PATCH 做更新？**  
> REST 规范中 PUT 表示"完整替换资源"，PATCH 表示"部分更新"，但对个人工具而言，区分这些动词带来的收益极低、反而增加记忆负担。统一用 POST 更简洁，后端路由也更容易理解：有 id 在路径上就是更新，没有就是新增。

**GET /api/plans 响应示例：**
```json
{
  "data": [
    {
      "id": "uuid",
      "departureDate": "2026-05-01",
      "holidayName": "劳动节",
      "fromStation": "北京南站",
      "toStation": "天津南站",
      "seatType": "SECOND_CLASS",
      "ticketCount": 1,
      "status": "PENDING_SALE",
      "saleDate": "2026-04-17",     // 由后端计算：departureDate - 14 天
      "daysUntilSale": 3,           // 距开售还有几天（前端展示用）
      "remark": null
    }
  ]
}
```

| `POST` | `/api/waitlist/sync` | Chrome Extension 同步数据（批量 upsert） |

## 六、Chrome Extension 设计

### 6.1 工作原理

```
用户打开 https://kyfw.12306.cn/otn/afterNate/queryMyHouBuOrder
          │
          ▼
Content Script 通过 fetch/XHR 拦截器监听网络响应
          │
          ├── 匹配到候补订单 API 响应
          │
          ▼
解析响应数据，提取候补订单列表
          │
          ▼
POST 到服务器 http://<tailscale-ip>:3005/api/waitlist/sync
（地址从 chrome.storage 读取，Options 页面可配置）
          │
          ▼
插件图标显示同步成功提示
```

### 6.2 服务器地址配置

由于服务部署在家庭 Linux 服务器、插件运行在 Mac 上，插件不能硬编码 `localhost`，需要一个可配置的服务器地址。

**设计方案：在插件 Options 页面配置服务器地址**

```
用户首次安装插件 → 右键插件图标 → "选项"
→ 填写服务器地址：http://<tailscale-ip>:3005
→ 保存到 chrome.storage.sync
→ Content Script 读取该地址拼接 API 路径
```

**manifest.json 核心配置：**
```json
{
  "manifest_version": 3,
  "name": "12306 助手",
  "permissions": ["scripting", "storage"],
  "options_page": "options.html",
  "host_permissions": [
    "https://kyfw.12306.cn/*",
    "http://*/*"
  ],
  "content_scripts": [
    {
      "matches": ["https://kyfw.12306.cn/otn/afterNate/*"],
      "js": ["content.js"]
    }
  ]
}
```

> `host_permissions` 使用 `http://*/*` 而非写死 `localhost`，是为了兼容 Tailscale IP（形如 `100.x.x.x`）和后续可能的局域网/公网地址。

### 6.3 数据同步安全性

- 插件与服务器通过 Tailscale 虚拟内网通信，流量不经过公网，天然安全
- `/api/waitlist/sync` 接口额外添加固定 Token 验证（Header: `X-Sync-Token`），Token 存储在插件 `chrome.storage` 和服务器 `.env` 中，防止局域网内其他设备误调用

## 七、定时任务设计

### 7.1 触发方式

通过 Next.js 的 `instrumentation.ts`（服务端初始化钩子）注册 node-cron 任务，服务启动后自动运行。

```typescript
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { startCronJobs } = await import('./lib/cron')
    startCronJobs()
  }
}
```

### 7.2 任务逻辑

```
每日 00:00 (Asia/Shanghai)
│
├── 查询所有 status = PENDING_SALE 或 ON_SALE 的出行计划
│
├── 遍历每条出行计划：
│   ├── 计算 saleDate = departureDate - 14 天
│   ├── 如果 today == saleDate - 1 天 → 发送"明天开售"通知
│   └── 如果 today == saleDate 当天   → 发送"今天开售"通知
│
└── 记录执行日志
```

### 7.3 时区处理关键点

> ⚠️ 这是定时任务中最容易出 bug 的地方。

```typescript
import { toZonedTime, fromZonedTime } from 'date-fns-tz'

const TIMEZONE = 'Asia/Shanghai'

// 获取今天在中国时区的日期（纯日期，不含时间）
function getTodayCN(): string {
  const now = new Date()
  const zonedNow = toZonedTime(now, TIMEZONE)
  return format(zonedNow, 'yyyy-MM-dd')
}
```

## 八、部署架构

### 8.1 网络拓扑

```
[家庭 Linux 服务器]
  · IP：192.168.x.x（局域网）
  · Tailscale IP：100.x.x.x（虚拟内网）
  · 运行：Next.js 服务（:3005）+ PostgreSQL（:5432）
  · 服务管理：pm2（保持进程常驻，崩溃自动重启）

[用户 Mac 电脑]
  · 通过 Tailscale 连接服务器（100.x.x.x:3005）
  · 浏览器访问前端页面
  · 浏览器安装 Chrome Extension，访问 12306 时同步候补数据
```

**为什么用 Tailscale？**
- 不需要配置路由器端口映射
- 流量走 WireGuard 加密隧道，比直接暴露公网端口安全
- 服务器无需公网 IP，只需联网即可
- 在外网（非家庭 WiFi）时，通过 Tailscale 依然能访问服务

### 8.2 进程管理（pm2）

```bash
# 在 Linux 服务器上，使用 pm2 管理 Next.js 进程
pnpm build
pm2 start pnpm --name "12306-help" -- start
pm2 save         # 保存进程列表
pm2 startup      # 设置开机自启
```

### 8.3 环境变量

```bash
# .env.example

# 数据库连接（Linux 服务器本地 PostgreSQL）

# Chrome Extension 同步接口鉴权 Token（随机字符串，自己生成）

# 服务监听端口（默认 3005）
PORT=3005

# Node 环境
NODE_ENV="production"
```

### 9.2 SCSS 组织约定

- 每个组件用 **CSS Modules**（`*.module.scss`），作用域隔离


## 十一、环境搭建步骤

### Mac 本地开发

```bash
# 1. 安装 PostgreSQL（仅开发时用，生产数据在 Linux 服务器）
brew install postgresql@16
brew services start postgresql@16
createdb 12306_help

# 2. 安装依赖
pnpm install

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env，DATABASE_URL 填写本地 PostgreSQL 地址

# 4. 执行数据库迁移
pnpm prisma migrate dev --name init

# 5. 启动开发服务器
pnpm dev   # 访问 http://localhost:3005

# 6. 加载 Chrome Extension（开发调试用）
# chrome://extensions → 开启开发者模式 → 加载已解压 → 选 extension/ 目录
# Options 页面填写：http://localhost:3005
```

### Linux 服务器生产部署

```bash
# 1. 安装 Node.js 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt-get install -y nodejs

# 2. 安装 pnpm 和 pm2
npm install -g pnpm pm2

# 3. 安装 PostgreSQL 16
sudo apt install postgresql-16

# 4. 创建数据库和用户
sudo -u postgres psql
> CREATE USER 12306user WITH PASSWORD 'your-password';
> CREATE DATABASE 12306_help OWNER 12306user;

# 5. 拉取代码，安装依赖，构建
pnpm install
pnpm prisma migrate deploy   # 生产环境迁移（不会重置数据）
pnpm build

# 6. pm2 启动并设置开机自启
pm2 start pnpm --name "12306-help" -- start
pm2 save
pm2 startup

# 7. 安装并配置 Tailscale
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

# 8. 验证：Mac 浏览器访问 http://100.x.x.x:3005（Tailscale IP）
```
