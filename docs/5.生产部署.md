> 访问方式：Mac 通过 Tailscale 内网连接


在 Mac 上，先把本地代码推到 Git 仓库（GitHub / 自建 Gitea 均可）。

```bash
cd /Users/kai/Desktop/code/repos/12306-help

# 确认 .env 已加入 .gitignore（不能提交到 git）
cat .gitignore | grep .env
```

## 第二步：Linux 服务器 · 安装基础环境

以下所有命令在**服务器**上执行（SSH 登录后）。

### 2.1 检查操作系统

```bash
lsb_release -a
# 推荐：Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS
```

### 2.2 安装 Node.js 22 LTS

> ⚠️ Prisma 7.x 要求 Node.js 版本 **≥ 20.19、22.12+ 或 24.0+**。  
> 推荐安装 22 LTS（长期支持），与本地开发版本接近。

```bash
# 通过 NodeSource 安装 Node.js 22 LTS
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs

# 验证版本
node -v    # 应显示 v22.x.x
npm -v
```

### 2.3 安装 pnpm 和 pm2

```bash
# 安装 pnpm（与本地一致的包管理器）
npm install -g pnpm

# 安装 pm2（进程管理器，保持 Node.js 进程常驻）
npm install -g pm2

# 验证
pnpm -v
pm2 -v
```

### 2.4 安装 PostgreSQL 16

```bash
# 添加 PostgreSQL 官方 apt 源
sudo apt-get install -y curl ca-certificates
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc --fail \
  https://www.postgresql.org/media/keys/ACCC4CF8.asc

sudo sh -c 'echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] \
  https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" \
  > /etc/apt/sources.list.d/pgdg.list'

sudo apt-get update
sudo apt-get install -y postgresql-16

# 启动服务并设置开机自启
sudo systemctl start postgresql
sudo systemctl enable postgresql

# 验证
sudo systemctl status postgresql
psql --version    # 应显示 psql (PostgreSQL) 16.x
```

## 第三步：Linux 服务器 · 创建数据库

### 3.1 创建专用数据库用户和数据库

```bash
# 切换到 postgres 系统用户，进入 psql
sudo -u postgres psql
```

在 psql 交互界面中执行：

```sql
-- 创建数据库用户（替换 'your-strong-password' 为真实强密码）
CREATE USER help_user WITH PASSWORD 'your-strong-password';

-- 创建数据库，指定 owner
CREATE DATABASE "12306_help" OWNER help_user;

-- 授予权限
GRANT ALL PRIVILEGES ON DATABASE "12306_help" TO help_user;

-- 退出
\q
```

### 3.2 测试连接

```bash
# 用新用户连接测试
psql -U help_user -d 12306_help -h localhost -c "SELECT current_user, current_database();"
# 如需输入密码则说明配置正确

# 如果提示"Peer authentication failed"，需要修改 pg_hba.conf
```

### 3.3 处理认证方式（如果连接报错）

PostgreSQL 默认对本地连接使用 `peer` 认证（验证系统用户名），需改为 `md5` 或 `scram-sha-256`：

```bash
# 找到 pg_hba.conf 位置
sudo -u postgres psql -c "SHOW hba_file;"
# 通常是 /etc/postgresql/16/main/pg_hba.conf

# 编辑配置
sudo nano /etc/postgresql/16/main/pg_hba.conf
```

找到以下行（`local` 开头的行）：
```
# 修改前
local   all             all                                     peer

# 修改后（改为 scram-sha-256）
local   all             all                                     scram-sha-256
```

```bash
# 重启 PostgreSQL 使配置生效
sudo systemctl restart postgresql

# 再次测试连接
psql -U help_user -d 12306_help -h localhost -c "SELECT 1;"
# 输入密码，显示 "1" 则成功
```

## 第四步：Linux 服务器 · 部署代码

### 4.1 克隆代码仓库

```bash
# 建议部署到 /opt 目录
sudo mkdir -p /opt/12306-help
sudo chown $USER:$USER /opt/12306-help

git clone <你的仓库地址> /opt/12306-help
cd /opt/12306-help

# 验证代码已拉取
ls -la
```

### 4.2 配置环境变量

```bash
# 基于模板创建 .env
cp .env.example .env

# 编辑 .env，填写所有配置项
nano .env
```

`.env` 内容说明（每项都必须填写）：

```bash
# 数据库连接 - 使用刚创建的用户和密码
DATABASE_URL="postgresql://help_user:your-strong-password@localhost:5432/12306_help"

# 企业微信应用配置（后续接入时填写）
WECOM_CORP_ID=""
WECOM_AGENT_ID=""
WECOM_SECRET=""
WECOM_TO_USER=""

# Chrome Extension 同步 Token - 自己生成一个随机字符串
# 生成方式：openssl rand -hex 32
EXTENSION_SYNC_TOKEN="在这里粘贴生成的随机字符串"

PORT=3000
```

生成随机 Token 的方法：

```bash
openssl rand -hex 32
# 输出类似：a3f8b2c1d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0
# 将这个值填到 EXTENSION_SYNC_TOKEN
```

### 4.3 安装依赖

```bash
cd /opt/12306-help

# --frozen-lockfile: 严格按 pnpm-lock.yaml 安装，不更新版本
pnpm install --frozen-lockfile

# 验证 Prisma Client 已生成
ls node_modules/.pnpm/@prisma*/
```

### 4.4 执行数据库迁移

```bash
cd /opt/12306-help

# 生产环境使用 migrate deploy（而非 migrate dev）
# deploy 只执行未运行的迁移，不会重置数据
pnpm prisma migrate deploy

# 预期输出：
# Loaded Prisma config from prisma.config.ts.
# Applying migration `20260517151401_init`
# Your database is now in sync with your schema.
```

> **`migrate dev` vs `migrate deploy` 区别：**
> - `migrate dev`：开发用，会交互式提问，可能重置数据库，自动生成新迁移文件
> - `migrate deploy`：生产用，只执行已有迁移文件，不生成新文件，不重置，**安全**

### 4.5 构建 Next.js

```bash
cd /opt/12306-help

pnpm build

# 预期看到类似输出：
# ✓ Compiled successfully
# ✓ Collecting page data
# ✓ Generating static pages
# Route (app) ...
```

> ⚠️ 构建可能需要 2-5 分钟，服务器内存建议 ≥ 1GB。如构建失败提示内存不足，见本文末尾的"常见问题"。

## 第五步：pm2 进程管理

### 5.1 创建 pm2 配置文件

在项目根目录创建 `ecosystem.config.js`（pm2 配置文件，**提交到 git**）：

```bash
cat > /opt/12306-help/ecosystem.config.js << 'EOF'
module.exports = {
  apps: [
    {
      name: '12306-help',
      script: 'pnpm',
      args: 'start',
      cwd: '/opt/12306-help',
      instances: 1,
      autorestart: true,
      watch: false,
      max_memory_restart: '512M',
      env: {
        NODE_ENV: 'production',
        PORT: 3000,
      },
      // 日志配置
      out_file: '/var/log/12306-help/out.log',
      error_file: '/var/log/12306-help/error.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
    },
  ],
}
EOF
```

```bash
# 创建日志目录
sudo mkdir -p /var/log/12306-help
sudo chown $USER:$USER /var/log/12306-help
```

### 5.2 启动服务

```bash
cd /opt/12306-help

# 用 ecosystem.config.js 启动
pm2 start ecosystem.config.js

# 查看状态（应显示 online）
pm2 status

# 查看实时日志
pm2 logs 12306-help --lines 50
```

### 5.3 设置开机自启

```bash
# 生成并执行开机自启命令
pm2 startup

# ⚠️ 上面命令会输出一行 sudo 命令，复制并执行它，例如：
# sudo env PATH=$PATH:/usr/bin /usr/lib/node_modules/pm2/bin/pm2 startup systemd -u ubuntu --hp /home/ubuntu

# 保存当前进程列表（重启后自动恢复）
pm2 save
```

### 5.4 验证自启

```bash
# 模拟重启测试（不真正重启服务器）
pm2 kill              # 停止 pm2 守护进程
pm2 resurrect         # 恢复保存的进程列表
pm2 status            # 应该重新显示 12306-help online
```

## 第六步：配置 Tailscale


```bash

ping 100.x.x.x

# 访问服务
```

Mac 浏览器打开 `http://100.x.x.x:3000` 看到页面即部署成功。

## 常见问题

### Q1：`pnpm build` 提示内存不足（ENOMEM）

```bash
# 临时增加 Node.js 可用内存（单位 MB）
NODE_OPTIONS="--max-old-space-size=1024" pnpm build

# 或者创建 swap 空间（永久方案）
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Q2：`pnpm prisma migrate deploy` 报 P1010 权限错误

数据库用户权限不足：

```bash
sudo -u postgres psql
> GRANT ALL ON SCHEMA public TO help_user;
> GRANT ALL PRIVILEGES ON DATABASE "12306_help" TO help_user;
> \q
```

### Q3：pm2 开机自启失败

```bash
# 重新生成 systemd 配置
pm2 unstartup
pm2 startup
# 执行输出的 sudo 命令
pm2 save
```

### Q4：Tailscale 访问超时

```bash
# 检查服务器防火墙
sudo ufw status
# 如果开启了 ufw，需要放行 3000 端口（仅限 Tailscale 网段）
sudo ufw allow from 100.64.0.0/10 to any port 3000
```

### Q5：`pnpm prisma migrate deploy` 在服务器提示 DATABASE_URL 问题

Prisma 7.x 的 `prisma.config.ts` 会从环境变量读取 URL，确保 `.env` 文件存在且格式正确：

```bash
# 检查 .env 是否存在
cat /opt/12306-help/.env | grep DATABASE_URL

# 必须包含用户名，格式：
# DATABASE_URL="postgresql://help_user:password@localhost:5432/12306_help"

# 临时测试：直接指定环境变量
DATABASE_URL="postgresql://help_user:password@localhost:5432/12306_help" pnpm prisma migrate deploy
```

### Q6：PostgreSQL 列名在原生 SQL 中报错

本项目 Prisma schema 中字段名为 camelCase（如 `orderNo`、`departureDate`），迁移到数据库后列名也是 camelCase。在写原生 SQL 时需加双引号：

```sql
-- 正确写法
SELECT "orderNo", "departureDate" FROM waitlist_orders;
DELETE FROM waitlist_orders WHERE "orderNo" = 'TEST001';

-- 错误写法（会报列不存在）
SELECT order_no FROM waitlist_orders;
```
