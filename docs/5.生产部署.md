### 2.4 安装 PostgreSQL 16

以下方式把 **PostgreSQL 16（语义版）** 安装到当前用户家目录下的 `~/postgresql`（`bin/`、`lib/` 等）；**数据目录**单独放在 `~/postgresql/data`。  
此前文档里 EnterpriseDB 的 `get.enterprisedb.com/...tar.gz` 直链常见 **HTTP 403**（CDN/访问策略），故改为 **postgresql.org 官方源码包编译安装**，x86_64 与 ARM64 同一套流程。

```bash
# 编译依赖（Ubuntu / Debian）；其它发行版请用对应包名安装 gcc、make、readline、zlib、flex、bison、openssl 开发头文件等
sudo apt-get update
sudo apt-get install -y build-essential libreadline-dev zlib1g-dev flex bison libssl-dev libicu-dev curl ca-certificates

# 安装前缀与数据、日志目录
export PG_PREFIX="$HOME/postgresql"
export PGDATA="$PG_PREFIX/data"
mkdir -p "$PGDATA" "$PG_PREFIX/log"

# 语义版号：请到 https://www.postgresql.org/ftp/source/ 对照当前 16.x 最新版修改（示例为 16.14）
PG_SRC_VERSION=16.14
cd /tmp
curl -fLO "https://ftp.postgresql.org/pub/source/v${PG_SRC_VERSION}/postgresql-${PG_SRC_VERSION}.tar.gz"
tar -xzf "postgresql-${PG_SRC_VERSION}.tar.gz"
cd "postgresql-${PG_SRC_VERSION}"

./configure --prefix="$PG_PREFIX"
make -j"$(nproc)"
make install

# 常用扩展（uuid-ossp 等），不需要可删去本段
cd contrib
make
make install

# 将命令加入 PATH（可写入 ~/.bashrc 持久化）
export PATH="$PG_PREFIX/bin:$PATH"

# 若数据目录尚未初始化，则创建数据库集群（只需执行一次）
if [ ! -f "$PGDATA/PG_VERSION" ]; then
  initdb -D "$PGDATA" -E UTF8 --locale=C.UTF-8 -U "$USER"
fi

# 前台调试用：postgres -D "$PGDATA"
# 常驻启动：日志写入 ~/postgresql/log/postgresql.log
pg_ctl -D "$PGDATA" -l "$PG_PREFIX/log/postgresql.log" start

# 查看是否在跑（或 pg_ctl -D "$PGDATA" status）
pg_isready -h localhost -p 5432

# 应显示 psql (PostgreSQL) 16.x
psql --version

# 重启机器后需要再次启动实例；开机自启见下方「§2.5」。
```

### 2.5 开机自启：`~/postgresql` 实例（systemd 用户服务）

用户级单元默认只在 **登录会话** 里生效；要让 **重启后、未 SSH 登录** 也自动跑 PostgreSQL，需为当前用户开启 **linger**（只需一次）。

```bash
# 若已由 §2.4 用 pg_ctl 手动启动，可先停掉，再交给 systemd 管（可选，避免重复占端口）
# "$HOME/postgresql/bin/pg_ctl" -D "$HOME/postgresql/data" stop -m fast

mkdir -p "$HOME/.config/systemd/user"
cat > "$HOME/.config/systemd/user/postgresql-home.service" <<'EOF'
[Unit]
Description=PostgreSQL (home directory install)
After=network-online.target
Wants=network-online.target

[Service]
Type=forking
Environment=PGDATA=%h/postgresql/data
ExecStart=%h/postgresql/bin/pg_ctl start -D %h/postgresql/data -l %h/postgresql/log/postgresql.log -w
ExecStop=%h/postgresql/bin/pg_ctl stop -D %h/postgresql/data -m fast
ExecReload=%h/postgresql/bin/pg_ctl reload -D %h/postgresql/data
TimeoutSec=300

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable postgresql-home.service
systemctl --user start postgresql-home.service
systemctl --user status postgresql-home.service

# 开机即使用户未登录也启动用户级服务（需 sudo，一次性）
sudo loginctl enable-linger "$USER"
```

**说明**：`%h` 会被 systemd 展开为家目录。日常可 `systemctl --user restart postgresql-home.service`；看日志：`journalctl --user -u postgresql-home.service -f`。

**约定**：第三步起默认按 **§2.4 家目录安装**（`$HOME/postgresql`、`$HOME/postgresql/data`、用户级服务 `postgresql-home`）。若改用发行版 apt 安装 PostgreSQL，请自行换成 `sudo -u postgres`、`/etc/postgresql/16/main/`、`sudo systemctl restart postgresql` 等布局。

## 第三步：Linux 服务器 · 创建数据库

### 3.1 创建专用数据库用户和数据库

```bash
# 能调用 psql、pg_isready 等（未写入 ~/.bashrc 时需每次先执行）
export PATH="$HOME/postgresql/bin:$PATH"

# 用超级用户进入 psql（与 §2.4 中 initdb -U "$USER" 一致，一般为当前 Linux 用户）
psql -h localhost -p 5432 -d postgres -U "$(whoami)"
```

在 psql 交互界面中执行：

```sql
-- 创建数据库用户（替换 'your-strong-password' 为真实强密码）
CREATE USER help_user WITH PASSWORD 'your-strong-password';

-- 创建数据库，指定 owner
CREATE DATABASE "12306_help" OWNER help_user;

-- 授予权限
GRANT ALL PRIVILEGES ON DATABASE "12306_help" TO help_user;

-- 退出
\q
```

### 3.2 测试连接

```bash
export PATH="$HOME/postgresql/bin:$PATH"

# 用新用户连接测试（TCP，走 127.0.0.1）
psql -U help_user -d 12306_help -h localhost -p 5432 -c "SELECT current_user, current_database();"
# 提示输入密码且能查出结果即正常

# 若报错与「Peer authentication」有关：说明没有使用 TCP（例如未加 -h localhost），或对 Unix 套接字走了 peer；请始终带 -h localhost，或按 §3.3 修改 pg_hba.conf 中 local 规则
```

### 3.3 处理认证方式（如果连接报错）

家用目录安装时，配置文件在数据目录下，不在 `/etc/postgresql/...`。

```bash
# 查看实际路径（可选）
export PATH="$HOME/postgresql/bin:$PATH"
psql -h localhost -p 5432 -d postgres -U "$(whoami)" -c "SHOW hba_file;"

# 一般为：
#   $HOME/postgresql/data/pg_hba.conf
nano "$HOME/postgresql/data/pg_hba.conf"
```

**两类连接要分清**：

1. **`psql -h localhost ...`**：走 TCP（`127.0.0.1`），核对文件里 **`host` / `hostssl` 且地址为 `127.0.0.1/32`、`::1/128`** 的行，方法建议为 **`scram-sha-256`**（PostgreSQL 16 常见默认）或 **`md5`**。  
2. **只写 `psql -U ... -d ...`（无 `-h`）**：走本机 **Unix 套接字**，对应 **`local`** 开头行；若为 **`peer`**，则系统用户名须与数据库用户名一致，否则易失败。应用与本文示例请统一使用 **`psql -h localhost`** 并配合密码认证。

示例（按你文件原有格式调整，勿盲目整段覆盖）：

```
# Unix 套接字：需要本地 psql 顶数据库名登录时可改为 scram-sha-256（改后需密码）
local   all             all                                     scram-sha-256

# IPv4 本机（与应用、Prisma 使用 host=localhost 一致）
host    all             all             127.0.0.1/32            scram-sha-256

# IPv6 本机（可选）
host    all             all             ::1/128                 scram-sha-256
```

使配置生效（任选其一）：

```bash
# 若使用 §2.5 的 systemd 用户服务
systemctl --user reload postgresql-home.service

# 或直接 reload
"$HOME/postgresql/bin/pg_ctl" -D "$HOME/postgresql/data" reload
```

再次测试：

```bash
export PATH="$HOME/postgresql/bin:$PATH"
psql -U help_user -d 12306_help -h localhost -p 5432 -c "SELECT 1;"
```

```bash
cat > "$HOME/repos/12306-help/ecosystem.config.js" << 'EOF'

module.exports = {
  apps: [
    {
      name: '12306-help',
      script: 'pnpm',
      args: 'start',
      cwd: path.join(os.homedir(), 'repos', '12306-help'),
      instances: 1,
      autorestart: true,
      watch: false,
      max_memory_restart: '512M',
      env: {
        NODE_ENV: 'production',
        PORT: 3005,

      // 日志配置
      out_file: '/var/log/12306-help/out.log',
      error_file: '/var/log/12306-help/error.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
    },
  ],
}
EOF
```

## 常见问题

### Q1：`pnpm build` 提示内存不足（ENOMEM）

```bash
# 临时增加 Node.js 可用内存（单位 MB）
NODE_OPTIONS="--max-old-space-size=1024" pnpm build

# 或者创建 swap 空间（永久方案）
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Q2：`pnpm prisma migrate deploy` 报 P1010 权限错误

数据库用户权限不足：

```bash
export PATH="$HOME/postgresql/bin:$PATH"
psql -h localhost -p 5432 -d postgres -U "$(whoami)" <<'SQL'
GRANT ALL ON SCHEMA public TO help_user;
GRANT ALL PRIVILEGES ON DATABASE "12306_help" TO help_user;
SQL
```

（若 `public` 的 owner 仍不是你期望的用户，也可在连上 `12306_help` 后执行 `ALTER SCHEMA public OWNER TO help_user;`，视迁移与对象归属而定。）

### Q3：pm2 开机自启失败

```bash
# 重新生成 systemd 配置
pm2 unstartup
pm2 startup
# 执行输出的 sudo 命令
pm2 save
```

### Q4：Tailscale 访问超时

```bash
# 检查服务器防火墙
sudo ufw status
```

### Q5：`pnpm prisma migrate deploy` 在服务器提示 DATABASE_URL 问题

Prisma 7.x 的 `prisma.config.ts` 会从环境变量读取 URL，确保 `.env` 文件存在且格式正确：

```bash
# 检查 .env 是否存在
cat "$HOME/repos/12306-help/.env" | grep DATABASE_URL

# DATABASE_URL="postgresql://help_user:password@localhost:5432/12306_help"

DATABASE_URL="postgresql://help_user:password@localhost:5432/12306_help" pnpm prisma migrate deploy
```

### Q6：PostgreSQL 列名在原生 SQL 中报错

本项目 Prisma schema 中字段名为 camelCase（如 `orderNo`、`departureDate`），迁移到数据库后列名也是 camelCase。在写原生 SQL 时需加双引号：

```sql
-- 正确写法
SELECT "orderNo", "departureDate" FROM waitlist_orders;
DELETE FROM waitlist_orders WHERE "orderNo" = 'TEST001';

-- 错误写法（会报列不存在）
SELECT order_no FROM waitlist_orders;
```
